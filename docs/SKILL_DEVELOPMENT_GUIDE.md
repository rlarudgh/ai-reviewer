## 스킬 파일 역할

### `SKILL.md`

스킬의 메인 진입점입니다. `/interview` 명령어 실행 시 Claude가 읽는 첫 번째 파일입니다.

**주요 역할:**

- 스킬 메타데이터 정의 (이름, 설명, 버전)
- 사용법 안내 (`/interview frontend`, `/interview all` 등)
- 3단계 면접 워크플로우 정의:
  1. **Phase 1 (Setup)**: 트랙 선택 + 이력서 업로드 + 프롬프트 로드
  2. **Phase 2 (Interview)**: Q&A 추적 + 면접 진행
  3. **Phase 3 (Evaluation)**: Q&A 로그 포함 평가 리포트

**수정 시 주의사항:**

- `name` 필드는 `/interview` 명령어와 일치해야 합니다
- Phase 순서를 변경하면 면접 흐름이 달라집니다
- 트랙 추가 시 `Phase 1: Setup` 섹션의 Track-to-Prompt Mapping 테이블에 새 행을 추가해야 합니다
- `all` 트랙 선택 메뉴도 함께 업데이트해야 합니다

---

### `prompts/interviewer-system.md`

모든 트랙에서 공통으로 사용하는 면접관 페르소나와 상호작용 규칙입니다.

**주요 역할:**

- 면접관의 톤과 태도 설정 (전문적이면서 편안한 분위기)
- 질문 방식 규칙 (한 번에 하나, 구체적이고 실무 중심)
- 피드백 방식 정의 (1-2문장, 긍정/보완/정정)
- 꼬리질문 전략 (답변 품질별 대응)
- 난이도 조절 로직

**수정 시 주의사항:**

- 이 파일은 트랙과 무관하게 모든 면접에 적용됩니다
- 질문 개수(8-12개)나 피드백 길이를 변경하면 전체 면접 경험이 달라집니다
- "한 번에 하나의 질문만" 규칙은 핵심 원칙입니다

---

### `prompts/{track}.md` (예: frontend.md, app.md, server.md)

각 트랙별 기술 주제와 질문 방향을 정의합니다.

**공통 구조:**

```markdown
# {Track} Track - {Tech Stack}

## Topic Guide

### {주제 1}

- 심화 주제 1
- 심화 주제 2

### {주제 2}

...

### 실무 시나리오 예시

- "상황 설명... 어떻게 대응하시겠어요?"

### 경력 질문 예시

- "~한 경험이 있나요? 구체적으로 설명해주세요"
```

**Topic Guide 작성 원칙:**

- 기본 개념 정의 대신 심화 주제와 실무 적용에 집중
- 구체적인 기술 스택 명시 (버전, 도구명 등)
- 트레이드오프와 의사결정 기준 포함
- 실무 시나리오는 구체적인 숫자/상황 제시

---

### `prompts/evaluator.md`

면접 종료 시 평가를 수행하는 에이전트의 프롬프트입니다.

**주요 역할:**

- 4가지 평가 항목 정의 (기술 이필도, 문제 해결력, 실무 경험, 커뮤니케이션)
- 평가 리포트 출력 형식 지정
- 평가 시 주의사항 안내

**수정 시 주의사항:**

- 평가 항목 가중치 변경 시 `README.md`와 동기화 필요
- 리포트 형식을 변경하면 출력 구조가 달라집니다
- `rubric.md`와 일관성을 유지해야 합니다

---

### `rubric.md`

각 평가 항목별 1-10점 세부 기준입니다.

**구조:**

- 4개 평가 항목 × 4개 등급 (9-10, 7-8, 4-6, 1-3)
- 각 등급별 구체적인 행동/답변 기술자 정의

**수정 시 주의사항:**

- `evaluator.md`의 평가 항목과 1:1 매칭되어야 합니다
- 점수 기준은 객관적이고 관찰 가능하게 작성
- 등급 간 경계가 모호하지 않도록 명확히 구분

## 새 트랙 추가하기

새로운 기술 스택 면접 트랙을 추가하는 단계별 가이드입니다.

### Step 1: 트랙 프롬프트 파일 생성

`prompts/{track-name}.md` 파일을 새로 만듭니다.

**필수 섹션:**

1. **Topic Guide**: 주요 기술 주제와 심화 내용
2. **실무 시나리오 예시**: 3-4개의 구체적인 상황 문제
3. **경력 질문 예시**: 3-4개의 실무 경험 질문

**예시 템플릿:**

```md
# {Track} Track - {Tech Stack}

{트랙 목표와 대상자를 한 문장으로 설명}

## Topic Guide

### {주제 A}

- 심화 주제 1: 구체적인 기술 내용
- 심화 주제 2: 트레이드오프와 선택 기준

### {주제 B}

...

### 공통 {도메인} 주제

- {도메인} 전반의 공통 지식

### 실무 시나리오 예시

- "{구체적인 상황}... 어떻게 대응하시겠어요?"

### 경력 질문 예시

- "{기술/상황}에 대한 경험이 있나요?"
```

### Step 2: SKILL.md에 트랙 등록

`SKILL.md`의 Phase 1 섹션에 새 트랙 매핑을 추가합니다.

```markdown
| Track | Prompt File |
|-------|------------|
| `frontend` | `prompts/frontend.md` |
| `backend` | `prompts/server.md` |
| `app` | `prompts/app.md` |
| `web-fullstack` | `prompts/frontend.md` + `prompts/server.md` |
| `{new-track}` | `prompts/{new-track}.md` |  # <-- 추가
```

**Track Selection Menu**도 함께 업데이트합니다:

```markdown
| # | 트랙 | 주요 평가 영역 |
|---|------|--------------|
| 1 | **Frontend** | ... |
| 2 | **Backend** | ... |
| 3 | **App** | ... |
| 4 | **Web Fullstack** | ... |
| 5 | **{New Track}** | {설명} |  # <-- 추가
```

### Step 3: README.md 업데이트

프로젝트 루트의 `README.md` 사용법 섹션에 새 트랙을 추가합니다.

### Step 4: 테스트

실제로 `/interview {new-track}` 명령을 실행하여:

- [ ] 올바른 프롬프트가 로드되는지
- [ ] 질문이 트랙 주제와 관련 있는지
- [ ] 평가가 정상적으로 작동하는지

## 프롬프트 수정하기

### Topic Guide 수정

**DO:**

- 구체적인 기술 버전/도구명 명시 ("React 18", "TanStack Query v5")
- 트레이드오프와 선택 기준 포함 ("A vs B 선택 기준")
- 실무 적용 사례 기반 질문 ("프로덕션에서 ~할 때")

**DON'T:**

- 기본 개념 정의 나열 ("React란?", "JSX란?")
- 이론 중심 질문 ("Virtual DOM 작동 원리 설명")
- 답변이 정해진 질문 ("React 18 출시 연도는?")

### 실무 시나리오 작성 팁

좋은 시나리오의 3요소:

1. **구체적인 상황**: "페이지 로드 시 LCP가 4초 이상입니다"
2. **명확한 목표**: "진단과 개선 프로세스를 설명해주세요"
3. **여러 접근법 가능**: 정답이 하나가 아닌 설계/의사결정 문제

### 경력 질문 작성 팁

좋은 경력 질문의 형태:

- "~한 경험이 있다면, 그때의 **결정 과정**을 설명해주세요"
- "**대안**과 **선택 이유**는 무엇이었나요?"
- "**실패**했던 부분과 **학습**은 무엇인가요?"

---

## 평가 기준 수정하기

### 평가 항목 가중치 변경

`prompts/evaluator.md`와 `README.md`의 가중치 표를 동시에 수정합니다.

예: 기술 이해도를 40% → 35%로 줄이고 문제 해결력을 30% → 35%로 늘리는 경우:

1. `evaluator.md`의 "## 평가 항목" 섹션 수정
2. `README.md`의 "## 평가 항목" 표 수정
3. `rubric.md`는 절대 가중치가 아닌 등급 기준이므로 수정 불필요

### 새로운 평가 항목 추가

**필요한 파일 모두 수정:**

1. `prompts/evaluator.md`: 새 항목 정의와 리포트 형식에 추가
2. `rubric.md`: 새 항목의 1-10점 세부 기준 추가
3. `README.md`: 평가 항목 표에 추가

## 테스트 및 검증

### 수동 테스트 체크리스트

새 트랙이나 프롬프트 수정 후 다음을 확인합니다:

**Phase 1 (Setup)**

- [ ] `/interview {track}` 실행 시 올바른 프롬프트 로드
- [ ] `/interview all` 시 트랙 선택 메뉴 표시
- [ ] 이력서 업로드 프롬프트 표시 (건너뛰기 가능)
- [ ] 이력서 제공 시 분석 후 맞춤형 첫 질문 생성

**Phase 2 (Interview)**

- [ ] 첫 질문이 트랙 주제와 관련 있음
- [ ] 한 번에 하나의 질문만 제시됨
- [ ] 답변 후 1-2문장 피드백 제공
- [ ] 답변 품질에 따라 적절한 꼬리질문 생성
- [ ] 한국어로 진행되고 기술 용어는 영어 유지

**Phase 3 (Evaluation)**

- [ ] "끝" 또는 "평가해줘" 입력 시 평가 시작
- [ ] 4개 평가 항목 모두 점수 산정
- [ ] 총점 계산 정확
- [ ] 강점/보완점이 구체적인 답변 내용 인용
- [ ] 추천 학습 방향이 실무 중심
- [ ] Q&A 전체 로그가 리포트에 포함
- [ ] 이력서 제공 시 후보자명 표시
- [ ] 리포트 파일이 `docs/interviews/`에 저장됨

### 품질 검증 기준

면접 질문이 다음 기준을 만족하는지 확인:

| 기준          | 설명                                              |
| ------------- | ------------------------------------------------- |
| **심화 수준** | 기본 개념 정의가 아닌 실무 적용/트레이드오프 중심 |
| **구체성**    | 기술 스택, 도구, 버전 등 구체적으로 언급          |
| **열린 질문** | 예/아니오로 끝나지 않고 설명/의사결정 요구        |
| **실무 연관** | 프로덕션 환경, 팀 협업, 장애 대응 등 실무 맥락    |

## 모범 사례

### 프롬프트 설계

1. **구체적이고 행동 중심으로 작성**
   - ❌ "React에 대해 질문"
   - ✅ "React 18 Concurrent Features의 실무 적용과 한계"

2. **트레이드오프를 드러내는 질문**
   - ❌ "Redux를 사용한 이유는?"
   - ✅ "Redux Toolkit과 Zustand 중 선택 기준과 한계"

3. **상황 맥락 제공**
   - ❌ "성능을 최적화하는 방법은?"
   - ✅ "페이지 로드 시 LCP가 4초 이상입니다. 진단과 개선 프로세스를 설명해주세요"

### 버전 관리

스킬 수정 시 의미 있는 버전을 기록합니다:

- **Major**: 새 트랙 추가, 평가 항목 구조 변경
- **Minor**: 기존 트랙 주제 확장, 질문 품질 개선
- **Patch**: 오타 수정, 문구 개선

`SKILL.md`의 메타데이터 섹션을 업데이트합니다:

```yaml
metadata:
  version: "2.0.0"
```

### 기여 워크플로우

1. 새 브랜치 생성: `feature/add-devops-track`
2. 프롬프트 파일 작성 및 SKILL.md, README.md 수정
3. 수동 테스트로 3가지 Phase 모두 검증
4. PR 설명에 테스트 결과와 변경 이유 기록

## 향후 계획

### 경력 수준별 면접 레벨 (신입/주니어/시니어)

현재는 "경력자(Experienced)"를 전제로 한 시니어 중심 면접만 지원합니다. 향후 다음과 같은 구조로 확장할 계획입니다.

#### 구현 범위

| 대상                | 질문 특성                     | 평가 기준                              | 실무 경험 질문             |
| ------------------- | ----------------------------- | -------------------------------------- | -------------------------- |
| **신입 (New Grad)** | 기본 개념 이해 + 간단한 적용  | 기초 지식, 학습 역량, 문제 해결 접근법 | 없음 또는 팀 프로젝트 경험 |
| **주니어 (1-3년)**  | 실무 적용 + 트레이드오프 인지 | 기술 적용력, 협업, 디버깅              | 있음 (규모 작음)           |
| **시니어 (5년+)**   | 아키텍처 설계 + 대규모 시스템 | 리더십, 설계 능력, 장애 대응           | 있음 (규모 있음)           |

#### 수정이 필요한 파일

1. **`SKILL.md`**
   - 명령어에 레벨 인자 추가: `/interview frontend junior`
   - 또는 시작 시 질문: "면접 대상자의 경력 수준을 알려주세요"

2. **`prompts/interviewer-system.md`**
   - 레벨별 페르소나 분기 (시니어 면접관 → 멘토링 중심 면접관)
   - 질문 전략 변경: 신입은 "X란 무엇인가요?" 가능, 시니어는 "X를 선택한 이유는?" 유지
   - 실무 경험 질문 비율 조정

3. **`prompts/{track}.md`**
   - 레벨별 Topic Guide 추가 또는 주제에 레벨 태그 부여
   - 예: `### React 기초 (신입)` / `### React 심화 (시니어)`

4. **`prompts/evaluator.md`**
   - 레벨 정보를 입력받아 해당 레벨의 rubric으로 평가하도록 수정
   - 평가 리포트에 레벨 표시

5. **`rubric.md`** — **가장 핵심이자 가장 큰 작업**
   - 같은 1-10점이라도 레벨별 기준이 완전히 달라야 함
   - 예: 기술 이필도 7점
     - **신입**: 핵심 개념을 정확히 이해하고 간단한 예시를 들 수 있음
     - **주니어**: 실무에서 사용핸 경험이 있고 일부 트레이드오프를 인지
     - **시니어**: 대규모 환경에서의 적용 경험과 아키텍처 설계 능력

#### 추천 구현 방식

```
/interview frontend junior     # 주니어 레벨 면접
/interview frontend senior     # 시니어 레벨 면접 (기본값)
```

또는:

```
/interview frontend
→ "면접 대상자의 경력 수준을 알려주세요 (신입/주니어/시니어)"
```
