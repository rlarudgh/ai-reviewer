# Prompt Engineering Guide

AI Reviewer의 프롬프트 설계 철학과 관리 방법.

---

## 설계 철학

### 1. 역할 부여 (Persona Assignment)

면접관 페르소나를 `interviewer-system.md`에 분리하여 일관된 톤 유지:

```
당신은 시니어 엔지니어 출신의 전문 기술 면접관입니다.
10년 이상의 실무 경험과 다수의 기술 면접 경험을 가진 면접관.
```

역할 부여 시 구체적인 배경(경력, 경험)을 명시하면 답변의 깊이와 톤이 달라짐.

### 2. 조건부 로직 (Conditional Logic)

후보자 답변 품질에 따른 꼬리질문 전략을 테이블로 정의:

| 답변 품질         | 다음 질문 전략      |
| ----------------- | ------------------- |
| 구체적이고 깊음   | 더 깊은 하위 주제로 |
| 일반적이지만 정확 | 구체적 사례 요청    |
| 모호하거나 표면적 | 다른 각도로 재질문  |

이 패턴을 사용하면 LLM이 상황에 맞게 분기 처리 가능.

### 3. 제약사항 명시 (Constraint Setting)

모호함을 줄이기 위해 구체적인 제약 설정:

- "한 번에 하나의 질문만"
- "피드백은 1-2문장 max"
- "기본 개념 정의보다는 실무 적용에 집중"

### 4. 출력 형식 고정 (Output Format)

평가 리포트의 일관성을 위해 마크다운 템플릿으로 출력 형식 강제:

```
## 기술 면접 총평
**트랙:** [Frontend / App / Server]
### 점수 요약
| 평가 항목 | 점수 (1-10) | 가중치 | 가중 점수 |
```

---

## 프롬프트 구조

```
interviewer-system.md    ← 공통 페르소나 + 이력서 기반 질문 (수정 빈도 낮음)
├── frontend.md          ← 트랙별 Topic Guide (수정 빈도 높음)
├── app.md
├── server.md            ← backend 트랙도 동일 파일 사용
└── (web-fullstack)      ← frontend.md + server.md 동시 로드
evaluator.md             ← 평가 로직 + Q&A 로그 포맷 (수정 빈도 중간)
rubric.md                ← 점수 기준표 (수정 빈도 낮음)
```

수정 시 영향 범위를 최소화하기 위해 관심사를 분리해둔 구조.

## 성능 향상 기법

### Context Injection (이력서 기반 질문)

이력서/포트폴리오 분석 결과를 면접 컨텍스트에 주입하여 맞춤형 질문 생성:

```
이력서 분석 결과:
- 기술 스택: React, Next.js, TypeScript, Spring Boot
- 경력: 5년차 프론트엔드 개발자
- 주요 프로젝트: 대규모 이커머스 플랫폼 리빌드
```

이 컨텍스트를 바탕으로 "이력서에 ~프로젝트를 담당하셨다고 했는데" 형태로 자연스럽게 연결.

### Q&A Tracking (대화 로깅)

면접 중 모든 질문-답변-피드백을 구조화하여 추적:

```
### Q1. [React 렌더링] React의 reconciliation 알고리즘을 최적화하는 전략은?
**답변:** (후보자 답변 요약)
**피드백:** (면접관 피드백)
```

평가 리포트 생성 시 이 로그를 그대로 포함하여 투명성과 재현성 확보.

### Chain of Thought (CoT)

평가 에이전트가 점수를 바로 출력하지 않고, 먼저 분석 과정을 거치도록 유도:

```
1. 대화 히스토리 전체를 검토
2. 각 질문-답변 쌍을 개별 평가
3. rubric 기준에 따라 점수 산정
4. 종합 평가 리포트 생성
```

단계를 명시하면 평가의 일관성과 정확도 향상.

### Few-shot 예시

질문 가이드에 실무 시나리오 예시를 포함하여 LLM이 질문의 수준과 스타일을 파악:

```
### 실무 시나리오 예시
- "대규모 폼(50+ 필드)에서 성능 저하가 발생합니다. 어떻게 최적화하시겠어요?"
- "페이지 로드 시 LCP가 4초 이상입니다. 진단과 개선 프로세스를 설명해주세요."
```

### Negative Prompting

하지 말아야 할 행동을 명시하여 품질 저하 방지:

```
- "X란 무엇인가요?" 보다는 "X를 선택한 이유와 그 한계는?" 형태
- Don't lecture
- Never list multiple questions at once
```

## 프롬프트 수정 체크리스트

수정 후 반드시 확인:

- [ ] `/interview-tester` 로 QA 진행
- [ ] 골든셋(`EXAMPLES/`)과 비교
- [ ] 다른 트랙에 영향이 없는지 확인 (`interviewer-system.md`, `evaluator.md` 공유 여부)
- [ ] rubric과 질문 난이도가 일치하는지 확인
