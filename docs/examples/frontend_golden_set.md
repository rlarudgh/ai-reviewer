### 상세 평가

#### 기술 이해도 (7.5/10)
- React Concurrent Features에 대한 이해도 높음. `useTransition`의 non-urgent update 개념을 정확히 설명하고, Suspense와의 연동까지 언급
- Next.js App Router에서 Server/Client Components의 경계를 실무 기준(interactivity 유무)으로 명확히 구분
- TypeScript 제네릭 설계에서 constrained generics의 필요성을 실제 API 응답 타이핑 사례로 설명
- Web Streams API나 RSC의 직렬화 제약 같은 심화 주제에서는 깊이가 약간 부족

#### 문제 해결력 (7.0/10)
- LCP 4초 문제 진단 시 Lighthouse → DevTools Performance 탭 → 번들 분석 도구로 이어지는 체계적 접근
- 대규모 폼 최적화에서 React Hook Form + zod 조합의 이유를 명확히 설명 (리렌더링 최소화 + 런타임 검증)
- "모든 케이스를 커버하는 솔루션은 없다"며 트레이드오프를 인정하는 태도 좋음
- 엣지 케이스(네트워크 단절 시 동작)에 대한 고려는 아쉬움

#### 실무 경험 (8.0/10)
- 마이크로 프론트엔드 도입 경험을 Module Federation의 한계와 webpack 대안 선택 이유까지 구체적으로 설명
- TanStack Query 마이그레이션 시 서버 상태와 클라이언트 상태를 분리한 전략이 실무적
- 디자인 시스템에서 compound component 패턴과 cva를 활용한 variant 관리까지 언급
- 프로덕션 장애 대응 경험(Sentry → 롤백 → 포스트모템)이 구체적

#### 커뮤니케이션 (7.5/10)
- 서론-본론-결론 구조로 답변하여 전달력이 좋음
- 기술 용어를 정확하게 사용하고, 필요시 비기술자에게 설명하듯 비유 활용
- 질문의 의도를 정확히 파악하여 핵심에 집중
- 복합 질문에서 후반부를 놓치는 경우 가끔 있음

## 면접 Q&A 전체 로그

### Q1. [React 렌더링] React 18의 Concurrent Features를 실무에서 어떻게 활용하고 있나요?
**답변:** useTransition으로 검색 필터링 시 UI 블로킹을 방지하고, Suspense와 함께 데이터 페칭 로딩 상태를 선언적으로 관리하고 있다고 답변. lane priority 개념까지 언급.
**피드백:** Concurrent Features의 실무 적용이 인상적입니다. Suspense boundary 설계 전략도 들어보고 싶네요.

### Q2. [Next.js] App Router에서 Server Components와 Client Components의 경계를 어떻게 나누나요?
**답변:** interactivity가 필요한 곳만 Client Components로 분리하고, 데이터 페칭은 Server Components에서 수행. use client 지시어 기준을 명확히 설명.
**피드백:** 실무 기준으로 명확하게 구분하고 계시네요. 번들 사이즈 측면에서의 영향도 좋은 포인트입니다.

### Q3. [TypeScript] API 응답 타입 설계 시 constrained generics를 어떻게 활용하나요?
**답변:** 제네릭에 extends로 기본 형태를 제약하고, zod 스키마와 연동하여 런타임 검증까지 수행. 실제 API 응답 타이핑 사례로 설명.
**피드백:** 정적 타입과 런타임 검증의 연동이 잘 되어 있습니다.

### Q4. [성능 최적화] 페이지 로드 시 LCP가 4초 이상입니다. 진단 프로세스를 설명해주세요.
**답변:** Lighthouse로 초기 진단 → DevTools Performance 탭으로 병목 확인 → webpack-bundle-analyzer로 번들 분석 순서로 접근. Code Splitting과 이미지 최적화를 해결책으로 제시.
**피드백:** 체계적인 진단 접근이 좋습니다. 네트워크 단절 상황에서의 동작도 고려해보시면 더 완벽할 것 같습니다.

### Q5. [상태 관리] 대규모 폼(50+ 필드)에서 성능 저하가 발생합니다. 어떻게 최적화하시겠어요?
**답변:** React Hook Form + zod 조합으로 리렌더링 최소화 + 런타임 검증. controlled보다 uncontrolled 방식의 장점을 설명.
**피드백:** 폼 최적화 전략이 구체적이고 실무적입니다.

### Q6. [실무 경험] 상태 관리 라이브러리 마이그레이션 경험이 있나요?
**답변:** Redux에서 TanStack Query로 마이그레이션. 서버 상태와 클라이언트 상태를 분리하는 전략을 설명. 캐시 무효화와 optimistic update 적용 사례 공유.
**피드백:** 마이그레이션 전략이 매우 실무적이네요. 점진적 마이그레이션 과정이 인상적입니다.

### Q7. [아키텍처] Feature-Sliced Design에서 features 레이어 간 의존성이 생기면 어떻게 해결하나요?
**답변:** shared 레이어에 공통 로직을 추출하거나, 이벤트 기반 통신으로 결합도를 낮춘다고 답변. 의존성 규칙 위반 시 린트로 탐지하는 방법도 언급.
**피드백:** FSD 의존성 관리에 대한 이해도가 높습니다.

### Q8. [실무 경험] 마이크로 프론트엔드 도입 경험이 있다면 설명해주세요.
**답변:** Module Federation을 활용한 마이크로 프론트엔드 도입 경험 공유. webpack 의존성 공유의 한계와 대안 선택 이유를 구체적으로 설명.
**피드백:** 마이크로 프론트엔드의 트레이드오프를 잘 이해하고 계십니다.

### Q9. [디자인 시스템] 디자인 시스템 컴포넌트 라이브러리를 만들어야 합니다. 아키텍처를 어떻게 설계하시겠어요?
**답변:** compound component 패턴과 cva를 활용한 variant 관리까지 언급. Headless UI 아키텍처로 유연성 확보하는 전략 설명.
**피드백:** 컴포넌트 설계 패턴에 대한 깊은 이해도가 돋보입니다.

### Q10. [장애 대응] 프로덕션에서 치명적 버그가 발견됐습니다. 대처 프로세스를 설명해주세요.
**답변:** Sentry로 에러 탐지 → 영향 범위 파악 → 핫픽스 배포 또는 롤백 → 포스트모템 진행 순서로 설명. 실제 경험 기반의 구체적인 사례 제시.
**피드백:** 장애 대응 프로세스가 체계적이고 실무 경험이 잘 드러납니다.
